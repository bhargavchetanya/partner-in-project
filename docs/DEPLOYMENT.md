# Free deployment guide

Everything below is free and needs no credit card. Total time: about 40 minutes.

| Part | Service | Free-tier facts |
|---|---|---|
| App (API + WebSockets + React) | **Render** free web service | 512 MB RAM, 0.1 CPU, 750 instance-hours/month. **Sleeps after 15 minutes** without HTTP requests or WebSocket messages; the next visit takes ~1 minute to wake it. Outbound SMTP is blocked (we use Brevo's HTTPS API). |
| Database | **MongoDB Atlas** free cluster (M0) | 512 MB storage, ~100 operations/second, one free cluster per project. |
| Email | **Brevo** free | 300 emails/day via API. |
| Hourly job + backups | **GitHub Actions** | Free for public repos; private repos get free monthly minutes — these jobs use well under 1 minute each. |

Profile photos are stored (compressed) in MongoDB, so no image host is needed.

> Throughout, replace `partner-in-project` with your Render service name if Render gives you a different URL (e.g. `partner-in-project-x1y2`). Your app URL is `https://<service-name>.onrender.com`.

---

## 1. MongoDB Atlas

1. Go to **https://cloud.mongodb.com** → sign up.
2. **Create** a cluster → choose **Free (M0)** → provider AWS, region **Mumbai (ap-south-1)** → Create.
3. **Database Access** → Add new database user → username `pipadmin`, *Autogenerate secure password* → copy it → role *Read and write to any database* → Add.
4. **Network Access** → Add IP address → **Allow access from anywhere** (`0.0.0.0/0`) → Confirm. (Render's free tier has no fixed outbound IP.)
5. **Database → Connect → Drivers** → copy the string, insert your password and add the database name `partner-in-project` before the `?`:
   ```
   mongodb+srv://pipadmin:<password>@cluster0.xxxxx.mongodb.net/partner-in-project?retryWrites=true&w=majority
   ```
   This is `MONGODB_URI`.

## 2. Brevo (email)

1. **https://www.brevo.com** → sign up (free plan).
2. **Settings → Senders, domains & dedicated IPs → Senders → Add a sender** → your Gmail → verify via the email Brevo sends.
3. **SMTP & API → API keys → Generate a new API key** → copy → `BREVO_API_KEY`.
4. `EMAIL_FROM` = the verified sender address.

> Emails sent from a Gmail address may land in spam. A custom domain verified in Brevo fixes this (optional).

## 3. Render (the app)

1. **https://render.com** → sign up **with GitHub** → allow access to the `partner-in-project` repository.
2. **New + → Blueprint** → select the repo → Render reads `render.yaml` → name stays `partner-in-project` → **Apply**.
   *(Or: New + → Web Service → repo → Runtime Node → Build `npm ci --include=dev && npm run build` → Start `npm start` → Instance **Free**.)*
3. Open the service → **Environment** and fill in (the three secrets are auto-generated by the blueprint):

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` |
| `NODE_VERSION` | `22` |
| `APP_URL` | `https://partner-in-project.onrender.com` (your exact URL, no trailing slash) |
| `MONGODB_URI` | from step 1 |
| `ADMIN_EMAILS` | your email(s), comma-separated |
| `SESSION_JWT_SECRET`, `TOKEN_ENCRYPTION_KEY`, `CRON_SECRET` | auto-generated (or `openssl rand -base64 48`) |
| `BREVO_API_KEY`, `EMAIL_FROM` | from step 2 |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | from step 4 |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_SERVER_TOKEN` | from step 5 |

4. **Save, rebuild and deploy.** The first build takes ~3–5 minutes. When the log shows `listening on :10000 (production)`, open the URL.

## 4. Google sign-in

1. **https://console.cloud.google.com** → project picker → **New project** "Partner in Project".
2. **APIs & Services → OAuth consent screen** (Google Auth Platform → Branding/Audience) → User type **External** → app name *Partner in Project*, support email, developer email → Save. Scopes: the default `openid`, `email`, `profile` are enough.
3. **Audience → Publish app** (status *In production*). With only these basic scopes, Google doesn't require app verification. While it stays in *Testing*, only test users you add can sign in.
4. **Credentials → Create credentials → OAuth client ID → Web application**:
   - Authorized JavaScript origins: `https://partner-in-project.onrender.com` and `http://localhost:5173`
   - Authorized redirect URIs:
     - `https://partner-in-project.onrender.com/api/auth/google/callback`
     - `http://localhost:5173/api/auth/google/callback`
5. Copy the client ID and secret into Render (and your local `.env`).

## 5. GitHub

**OAuth Apps** (for "Connect GitHub account" — GitHub allows one callback URL per app, so make two):
1. **github.com → Settings → Developer settings → OAuth Apps → New OAuth App**
   - *Production*: homepage `https://partner-in-project.onrender.com`, callback `https://partner-in-project.onrender.com/api/github/callback`
   - *Development*: homepage `http://localhost:5173`, callback `http://localhost:5173/api/github/callback`
2. In each, **Generate a new client secret**. Production values → Render; development values → local `.env`.

**Server token** (for username-only links; GitHub's GraphQL API needs a token):
1. **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. Expiration 90 days · Repository access **Public repositories (read-only)** · no extra permissions → Generate → `GITHUB_SERVER_TOKEN`.

## 6. GitHub Actions (hourly job + daily backup)

Repository → **Settings → Secrets and variables → Actions → New repository secret**:

| Secret | Value |
|---|---|
| `APP_URL` | `https://partner-in-project.onrender.com` |
| `CRON_SECRET` | copy the value from Render → Environment |
| `MONGODB_URI` | same as Render |

Then **Actions** tab → enable workflows → run **Hourly jobs** and **Daily backup** once with *Run workflow* to check they pass. Keep the repository **private** so backups are only visible to you.

## 7. Seed the catalogue and demo data (from your Mac)

The default skill catalogue is created automatically on first start. To add demo students and team posts for the evaluation:

```bash
# in the project folder, with MONGODB_URI in .env pointing at Atlas
npm run seed:demo
```

## 8. Verify the deployment

- [ ] `https://<app>/api/health` returns `{"status":"ok","db":"up"}`
- [ ] Landing page loads over **https** (padlock) on a phone and a laptop
- [ ] Register with email → OTP email arrives → verified → onboarding
- [ ] Log out → **Continue with Google** works and lands on the dashboard
- [ ] GitHub page → link a username → all repositories appear → skill suggestions appear on Skills
- [ ] **Connect GitHub account** (OAuth) shows the "Verified via GitHub sign-in" badge
- [ ] Create a team post → admin (your `ADMIN_EMAILS` account) sees it in **Admin → Post approvals** → approve → it shows in Team Finder
- [ ] Apply from a second account → leader gets a notification → accept → team chat works live in two browsers
- [ ] Settings → email notifications toggle works

## Before the demo

The free service sleeps after 15 idle minutes. **Open the site 2–3 minutes before presenting.** Optionally, add a free monitor (e.g. UptimeRobot) that requests `/api/health` every 10–14 minutes; a full month of that uses ~720 of the 750 free hours, so only do it for one service.

## Updating

Push to `main` → Render redeploys automatically.

## Limits to mention honestly

- Cold start after inactivity (~1 min) on Render's free tier.
- Atlas M0: 512 MB and ~100 ops/s — fine for a demo and a few thousand users; QR7 load targets (200–500 concurrent users) are limited by 0.1 CPU and these ops limits.
- Brevo free: 300 emails/day.
- Free tiers can change; the code uses a plain Node server and a standard MongoDB URI, so it can move to another host without changes.
